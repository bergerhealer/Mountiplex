# Custom Converter Example

Registering a converter, using it from a template cast, and getting the `Converter` object itself. Background:
[conversion.md](../conversion.md) (principles, cost, chaining, built-ins) and
[template-syntax.md](../template-syntax.md#type-casts-exposed-real).

All code on this page was run against Mountiplex. The numbers in comments are the real outputs.

## The Types

A real class with `int` Celsius values, and a value type the API wants to expose instead:

```java
public class Thermometer {                       // the "real" class, imagine it is an internal one
    private int celsius = 20;
    private List<Integer> readings = new ArrayList<>(Arrays.asList(5, 10, 15));
    public int getCelsius() { return celsius; }
    public void setCelsius(int c) { this.celsius = c; }
}

public final class Temperature {                 // the type shown to callers
    public final double kelvin;
    public Temperature(double kelvin) { this.kelvin = kelvin; }
    public static Temperature ofCelsius(int c) { return new Temperature(c + 273.15); }
    public int toCelsius() { return (int) Math.round(kelvin - 273.15); }
}
```

## 1. Registering with Annotations

One static method per direction. The types come from the method signature, so no attribute is needed:

```java
public class TemperatureConversion {
    @ConverterMethod
    public static Temperature toTemperature(int celsius) {
        return Temperature.ofCelsius(celsius);
    }

    @ConverterMethod
    public static int toCelsius(Temperature temperature) {
        return temperature.toCelsius();
    }
}

Conversion.registerConverters(TemperatureConversion.class);      // early, see conversion.md
```

When the real type cannot be written in Java (an internal class), name it as text and mark types that might not exist as optional:

```java
@ConverterMethod(input = "net.example.internal.Reading", optional = true)
public static Temperature fromReading(Object reading) { /* ... */ }

@ConverterMethod(output = "net.example.internal.Reading", acceptsNull = true, cost = 5)
public static Object toReading(Temperature t) { /* ... */ }
```

### Registering a Converter Object

The same, by subclassing. `DuplexConverter` registers both directions, and `getCost()` sets the priority:

```java
Conversion.registerConverter(new DuplexConverter<Double, Temperature>(Double.class, Temperature.class) {
    @Override public Temperature convertInput(Double kelvin) { return new Temperature(kelvin); }
    @Override public Double convertOutput(Temperature t) { return t.kelvin; }
    @Override public int getCost() { return 5; }
});
```

After this, `Conversion.find(Double.class, Temperature.class)` is this converter (`cost=5`) and
`find(Temperature.class, Double.class)` is its reverse.

## 2. Using It in a Template

A cast `(Exposed) Real` makes the handle show `Temperature` where the class uses `int`. Import the exposed type
(see [Imports and Type Names](../template-syntax.md#imports-and-type-names)):

```
import java.util.List;
import my.pkg.Temperature;

class my.pkg.Thermometer {
    public (Temperature) int getCelsius();                       // return type
    public void setCelsius((Temperature) int celsius);           // parameter
    private (List<Temperature>) List<Integer> readings;          // field, generics
}
```

The handle (generated by the Gradle plugin; written by hand here) uses `Converted` element types for the
members that have a cast:

```java
@Template.InstanceType("my.pkg.Thermometer")
public abstract class ThermometerHandle extends Template.Handle {
    public static final ThermometerClass T = Template.Class.create(ThermometerClass.class, MyTemplates.RESOLVER);

    public abstract Temperature getCelsius();
    public abstract void setCelsius(Temperature celsius);
    public abstract List<Temperature> getReadings();

    public static class ThermometerClass extends Template.Class<ThermometerHandle> {
        public final Template.Method.Converted<Temperature> getCelsius = new Template.Method.Converted<Temperature>();
        public final Template.Method.Converted<Void> setCelsius = new Template.Method.Converted<Void>();
        public final Template.Field.Converted<List<Temperature>> readings = new Template.Field.Converted<List<Temperature>>();
    }
}
```

Use:

```java
ThermometerHandle h = ThermometerHandle.createHandle(new Thermometer());
h.getCelsius();                           // 293.15K (the real value is 20)
h.setCelsius(new Temperature(300.15));    // the real field is now 27
List<Temperature> readings = h.getReadings();   // a live view of the Integer list
readings.add(Temperature.ofCelsius(30));        // the real list is now [5, 10, 15, 30]
```

No converter was registered for `List<Integer>` to `List<Temperature>`: the built-in `CollectionConversion` found the
element converter `int <> Temperature` registered in step 1 and wrapped the list.
Both directions of the element converter were needed, since the view can be written to. For a plain field read and write a
`DuplexConverter` pair is also needed. A method return only needs `real -> exposed`, a parameter `exposed -> real`.

The converters are looked up when the handle class initializes, so register them **before** the handle class is first used.

## 3. Getting the Converter Object

For use outside of templates, ask the registry. Keep results in static fields:

```java
Converter<Integer, Temperature> c = Conversion.find(int.class, Temperature.class);
c.convert(25);                                        // 298.15K
c.toString();                                         // AnnotatedConverter[cost=1, int -> Temperature]

DuplexConverter<Integer, Temperature> d = Conversion.findDuplex(Integer.class, Temperature.class);
d.convert(0);                                         // 273.15K
d.convertReverse(new Temperature(373.15));            // 100

InputConverter<Temperature> any = Conversion.find(Temperature.class);   // input decided per value
Temperature t = any.convert("12");                    // String -> Integer -> int -> Temperature
```

Generic types need `TypeDeclaration`s. Parse them from text, or use `TypeDeclaration.fromClass`:

```java
Converter<Object, Object> toColl = Conversion.find(
        TypeDeclaration.parse("java.util.List<Integer>"),
        TypeDeclaration.parse("java.util.Collection<my.pkg.Temperature>"));
toColl.convert(Arrays.asList(1, 2));                  // a live Collection<Temperature>
```

`find` returns `null` if there is no path, so check for it when the types are dynamic.

## 4. What the Registry Does With It

Printing converters shows the chains. Results with the types above (`String` input):

```
ChainConverter[cost=2, String -> Temperature] {
  -> NumberConversion$3[cost=1, String -> Integer]
  -> NullConverter[cost=0, Integer -> int]
  -> AnnotatedConverter[cost=1, int -> Temperature]
}
```

- A `String` converts to a `Temperature` by chaining the built-in parser with the converter from step 1.
- A `Float` also converts, via `Number -> Integer`, which drops the decimals. Chains are found for any input, so check these results when precision matters.
- With a converter that produces a subtype (`Thermometer -> ArrayList<String>`), `find(Thermometer, Collection<String>)` finds it too:
  the converter for the subtype is chained with the built-in `ArrayList<String> -> Collection<String>`.
- A converter with a higher `cost`, such as the 5 above, is only picked when it is part of the cheapest path.

Print the whole search tree for an output type with `Conversion.debugTree(String.class, Temperature.class)`.
